Scaling security review with static analysis

YM
Yusuf M
Application Security
February 5, 2026 Published
9 min read Reading time

When your engineering org is small, having a security person review every pull request is feasible. When you're at hundreds of engineers shipping daily, it isn't.

The problem with manual review

Manual security review is slow, inconsistent, and doesn't scale. It creates a bottleneck that incentivizes engineers to work around the process. We wanted security to happen automatically and invisibly.

Choosing what to automate

We focused on vulnerability classes with high precision and high prevalence:

  • Hardcoded credentials and secret material in code
  • Unsafe deserialization patterns
  • Known-vulnerable dependency versions
  • Common cryptographic misuse patterns

The toolchain

We built on top of Semgrep with custom rules for our internal frameworks, integrated directly into CI with a fail-open stance — if the analyzer crashes, the build continues. Security tooling should never be a reliability risk for shipping.

# .semgrep.yml
rules:
  - id: no-raw-sql-interpolation
    patterns:
      - pattern: db.query("..." % ...)
      - pattern: db.query("..." + ...)
    message: "Use parameterized queries."
    severity: ERROR
    languages: [python]
A security tool that developers learn to ignore is a liability, not an asset. Precision matters more than recall.

Results

After 12 months, automated tooling catches ~60% of issues that previously required manual review. Our team now focuses on harder, context-dependent problems that can't be automated.
